# Requirements Analysis

## 1. Product Overview

В рамках QA-практики рассматривается веб-приложение для работы с каталогом товаров, пользователями, корзиной и заказами.

Основные пользовательские сценарии:

- регистрация и авторизация;
- просмотр каталога;
- просмотр карточки товара;
- добавление товара в корзину;
- изменение количества товаров;
- удаление товаров;
- оформление заказа;
- просмотр истории заказов.

## 2. Main User Roles

### Guest

Неавторизованный пользователь может:

- просматривать доступные товары;
- открывать карточки товаров;
- выполнять поиск и фильтрацию.

Доступ к операциям, связанным с персональными данными и заказами, ограничен.

### User

Авторизованный пользователь может:

- управлять своей корзиной;
- оформлять заказы;
- просматривать свои заказы;
- изменять доступные персональные данные.

### Administrator

Администратор имеет дополнительные права:

- управление товарами;
- просмотр заказов;
- управление пользователями;
- доступ к административным функциям.

## 3. Functional Requirements

### Authentication

Система должна:

- позволять пользователю авторизоваться с корректными учётными данными;
- отклонять некорректные учётные данные;
- валидировать обязательные поля;
- ограничивать доступ к защищённым ресурсам без авторизации.

### Product Catalog

Пользователь должен иметь возможность:

- просматривать список товаров;
- открывать карточку товара;
- видеть актуальную информацию о товаре;
- искать товары;
- использовать доступные фильтры.

### Cart

Пользователь должен иметь возможность:

- добавить товар в корзину;
- изменить количество товара;
- удалить товар;
- увидеть актуальную итоговую стоимость.

### Orders

Пользователь должен иметь возможность:

- оформить заказ;
- увидеть информацию о созданном заказе;
- просматривать историю своих заказов.

Система не должна позволять пользователю получать доступ к заказам других пользователей.

## 4. Key Risks

Наиболее критичными считаю следующие области:

1. Авторизация и контроль доступа.
2. Работа с персональными данными.
3. Расчёт стоимости заказа.
4. Изменение количества товаров.
5. Создание заказа.
6. Согласованность данных между UI, API и базой данных.
7. Обработка некорректных пользовательских данных.

## 5. Testing Priorities

В первую очередь необходимо проверить:

- авторизацию;
- права доступа;
- добавление товаров;
- работу корзины;
- расчёт стоимости;
- оформление заказа;
- сохранение данных заказа.

После проверки критичных сценариев можно расширять покрытие менее рискованных функций.

## 6. Questions / Ambiguities

Перед полноценным тестированием необходимо уточнить:

- существует ли ограничение на максимальное количество товара;
- может ли цена товара изменяться после добавления в корзину;
- что происходит с корзиной после выхода пользователя из аккаунта;
- можно ли отменить созданный заказ;
- какие статусы может иметь заказ;
- какие поля являются обязательными при оформлении;
- какие действия доступны каждой пользовательской роли.

## 7. Expected Test Coverage

На основании требований планируется покрыть:

- позитивные сценарии;
- негативные сценарии;
- граничные значения;
- проверки ролей и прав доступа;
- бизнес-правила;
- API;
- данные в базе;
- критические пользовательские сценарии.
