# API Testing

## 1. Цель

Проверить корректность работы REST API, обработку позитивных и негативных сценариев, авторизацию, валидацию входных данных и структуру ответов.

Для тестирования используются HTTP-запросы и JSON.

---

## 2. Авторизация

### POST /auth/login

**Назначение:** авторизация пользователя.

**Пример запроса:**

```json
{
  "email": "user@example.com",
  "password": "Password123"
}
```

**Ожидаемый ответ:**

HTTP 200.

Ответ содержит токен авторизации.

```json
{
  "token": "..."
}
```

### Проверки

* корректные учётные данные → успешная авторизация;
* неверный пароль → ошибка авторизации;
* несуществующий пользователь → ошибка авторизации;
* пустой email → ошибка валидации;
* пустой пароль → ошибка валидации;
* некорректный формат email → ошибка валидации.

---

## 3. Получение товара

### GET /products/{id}

**Пример запроса:**

```text
GET /products/15
```

**Проверки:**

* существующий товар → HTTP 200;
* корректный идентификатор → возвращается нужный товар;
* отсутствующий товар → HTTP 404;
* невалидный идентификатор → корректная обработка ошибки;
* структура JSON соответствует API-контракту.

### Проверка ответа

Пример:

```json
{
  "id": 15,
  "name": "Product",
  "price": 3490
}
```

Проверяется наличие обязательных полей:

* `id`;
* `name`;
* `price`.

Также проверяется тип данных каждого поля.

---

## 4. Создание заказа

### POST /orders

**Предусловия:**

Пользователь авторизован.

**Пример запроса:**

```json
{
  "items": [
    {
      "productId": 15,
      "quantity": 2
    }
  ]
}
```

### Позитивный сценарий

При корректных данных:

* возвращается успешный HTTP-код;
* создаётся заказ;
* возвращается идентификатор заказа;
* в ответе присутствует информация о заказе.

### Негативные сценарии

Проверяются:

* пустой список товаров;
* несуществующий товар;
* количество товара равное 0;
* отрицательное количество;
* отсутствие обязательных параметров;
* запрос без авторизации;
* запрос с недействительным токеном.

---

## 5. Проверка авторизации

Защищённые endpoints проверяются с разными вариантами авторизации:

| Сценарий               | Ожидаемый результат |
| ---------------------- | ------------------- |
| Корректный токен       | Доступ разрешён     |
| Отсутствует токен      | Доступ запрещён     |
| Недействительный токен | Доступ запрещён     |
| Истёкший токен         | Доступ запрещён     |
| Недостаточно прав      | Доступ запрещён     |

---

## 6. Проверка HTTP-кодов

Используются проверки соответствия результата операции ожидаемому HTTP-коду.

Примеры:

* `200 OK` — успешное получение или выполнение операции;
* `201 Created` — ресурс успешно создан;
* `400 Bad Request` — некорректные входные данные;
* `401 Unauthorized` — отсутствует или некорректна аутентификация;
* `403 Forbidden` — недостаточно прав;
* `404 Not Found` — ресурс не найден;
* `500 Internal Server Error` — внутренняя ошибка сервера.

---

## 7. Проверка структуры JSON

Проверяется:

* наличие обязательных полей;
* типы данных;
* значения полей;
* вложенные объекты;
* массивы;
* отсутствие неожиданных изменений структуры ответа.

Пример:

```json
{
  "id": 15,
  "name": "Product",
  "price": 3490,
  "available": true
}
```

Проверяем:

* `id` содержит число;
* `name` содержит строку;
* `price` содержит числовое значение;
* `available` содержит boolean.

---

## 8. Проверка API и базы данных

После создания заказа через API можно проверить результат непосредственно в базе данных.

Пример последовательности:

```text
POST /orders
      ↓
Получение orderId
      ↓
Запрос в БД
      ↓
Проверка заказа
      ↓
Сравнение данных
```

Проверяются:

* идентификатор заказа;
* пользователь;
* состав заказа;
* количество товаров;
* итоговая стоимость;
* статус заказа.

Это позволяет проверить не только API-ответ, но и корректность сохранения данных.

---

## 9. Основные риски

При API-тестировании особое внимание уделяется:

* авторизации и контролю доступа;
* обработке некорректных данных;
* корректности бизнес-логики;
* целостности данных;
* соответствию API-контракту;
* обработке ошибок;
* защите данных пользователей.
